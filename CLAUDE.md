# Verbloom

Desktop app built with [Wails v2](https://wails.io): Go backend, React 19 + TypeScript + shadcn/ui (Tailwind v4) frontend rendered in a native WebView.

The app welcomes the OS user by name and records camera video and audio, with pause and resume, into `tmp/recording-<timestamp>.mp4`. The directory is relative to the working directory and can be overridden with `VERBLOOM_RECORDINGS_DIR`.

## Commands

Run everything through `make` (run `make help` to list targets).

| Task                         | Command                  |
| ---------------------------- | ------------------------ |
| Run the app with hot reload  | `make dev`               |
| Lint + all tests (the gate)  | `make check`             |
| Tests only                   | `make test`              |
| Coverage (Go + TS)           | `make coverage`          |
| Format Go + TS               | `make fmt`               |
| Regenerate `frontend/wailsjs`| `make bindings`          |
| Same gate inside Docker      | `make docker-check`      |
| Linux binary via Docker      | `make docker-build`      |

Frontend-only: `cd frontend && npm run check`.
Linux builds need `-tags webkit2_41` (Ubuntu 24.04+ ships WebKitGTK 4.1 only); the Makefile, `wails.json`, `.golangci.yml` and VS Code settings already pass it. **Known limitation: recording does not work in the Linux desktop window yet.** WebKitGTK 2.52 can only record MP4 (no WebM at all), and its MP4 recorder needs GStreamer's `isofmp4mux` element (from gst-plugins-rs), which Ubuntu 24.04 doesn't package. `isTypeSupported('video/mp4')` still returns true; `start()` then throws "The MediaRecorder is unsupported on this platform". Until the plugin is installed or bundled, record in Chrome via `make dev` at http://localhost:34115 (Wails), not :5173 (Vite, no Go backend). The frontend tries each format until a recorder actually starts; Go saves MP4 directly and converts WebM (Firefox) to MP4 with ffmpeg.

## Layout

```
main.go                     entry point only: config, embed assets, wails.Run
internal/app/               Wails wiring: config, window options, lifecycle hooks, bound services
internal/profile/           current OS user (welcome name)
internal/recording/         streams chunks to disk, validates, converts WebM→MP4 (ffmpeg), saves
internal/webview/           Linux cgo: enables camera/mic in WebKitGTK for wails:// pages only
frontend/src/app/           root component and app-wide providers
frontend/src/features/<f>/  api/ lib/ hooks/ components/ + index.ts (public API)
frontend/src/shared/ui/     shadcn/ui components (add with `npx shadcn@latest add <name>`)
frontend/src/shared/lib/    cross-feature helpers (no feature imports)
frontend/wailsjs/           GENERATED by Wails — never edit by hand
```

## Rules that are not negotiable

- **`make check` must pass** before any task is reported as done. Never weaken a linter rule, threshold or tsconfig flag to get there; fix the code. A `//nolint` or `eslint-disable` needs a specific rule and a written reason.
- **Small files.** Go: ≤ 300 lines per file, functions ≤ 60 lines. TS: ≤ 200 lines per file, functions ≤ 80 lines. Both are enforced by the linters. Split by responsibility before hitting the limit, not after.
- **Boundaries.** Business logic lives in `internal/<domain>`, never in `main.go` or `internal/app`. On the frontend, only `features/*/api/` may import `@wailsjs/*`, and features import each other only via their `index.ts`. ESLint enforces both.
- **Every change ships with tests**: table-driven Go tests next to the code, Vitest + Testing Library tests next to the component or hook. Coverage threshold is 80%.
- After changing an exported method on a bound Go service, run `make bindings` (or `make docker-bindings` if WebKit headers are missing locally) and commit the regenerated `frontend/wailsjs`.
